# handoff-260217-3.md

## Scope / Problem framing

Iterate UI/UX refinements and small correctness improvements in the Textual skating-system app. Keep the core scoring algorithm and transcript generation unchanged.

Primary goals:
- Improve user-facing messaging (no UUIDs in UI).
- Add a safe “delete competition” workflow on home screen (future-proof via obsoleting if feasible).
- Improve default layout (transcript panel hidden by default).
- Fix/standardize clipboard copy binding (vim yank).
- Ensure home screen table refreshes after editing a competition.

Stretch goal:
- Improve dead-cell styling/cutoff visualization for tie-break cases to better match transcript cutoffs, without changing algorithm.

Non-goals:
- Do not change scoring logic, transcript logic, or ranking outcomes.
- Do not refactor domain architecture broadly.
- Do not force `Enter` as open/edit (leave `e` as canonical).

---

## Specs

### User messaging

- **S-260217-3.1** Competition screen: when compute fails due to missing ranks/scores, show the error using **judge/entry display names**, not UUIDs.
  - Scope: competition screen only.
  - Message should identify the judge and the affected entry/entries.

### Delete / obsolete competition (home screen)

- **S-260217-3.2** Home screen: add keybinding `x` to delete the currently selected competition.

- **S-260217-3.3** Delete requires confirmation modal (single-step):
  - Press `x` → modal appears
  - Press `y` confirms deletion
  - Press `n` cancels
  - Esc should also cancel (if easy / standard).

- **S-260217-3.4** Prefer “future-proof” deletion: mark competition as **obsolete** (soft delete) and hide it from the home list.
  - If feasible without broad refactor, add a boolean field on Competition (e.g., `is_obsolete: bool = False`).
  - Home competitions list must filter out obsolete competitions.
  - Deleting sets the flag to `True`.

- **S-260217-3.5** If soft-delete is not feasible with minimal changes, fallback:
  - Remove the competition from the event’s competitions collection in-memory.
  - Do not delete judges/entries globally.

### Transcript panel default visibility

- **S-260217-3.6** Transcript panel is hidden/collapsed by default when entering the competition screen.
  - Existing toggle behavior remains.

### Home table refresh after returning

- **S-260217-3.7** After exiting competition editing screen and returning to home screen, the home competitions DataTable must refresh to reflect updates (e.g., renamed competition/judges/entries visible on home list).

### Clipboard copy / yank

- **S-260217-3.8** Copy DataTable contents uses `y` (vim yank metaphor) instead of `Ctrl+C`.
  - `Ctrl+C` must not be required for copy.

- **S-260217-3.9** After yank, show a short confirmation message: “Table copied to clipboard”.

- **S-260217-3.10** Yank copies **exactly what the user sees** in the active DataTable:
  - visible headers
  - visible rows
  - visible cell strings
  - in visible order

### Stretch: dead-cell visualization alignment in tie-breaks

- **S-260217-3.11 (stretch)** Improve dead/active cell styling so that, for each entry, the **last active column** matches the transcript cutoff used to resolve that entry.
  - Transcript indicates cutoffs like “resolved at 1–3” or “escalated to 1–4”.
  - For entries resolved at 1–3, columns after 3 should be styled as dead for that entry (unless already dead by other rules).
  - Do not change any underlying scoring logic or transcript generation.
  - If implementation is complex or risks correctness, skip this stretch goal.

## Implementation suggestions

### I-260217-3.1 Resolve IDs → names for missing-score messaging

- If compute raises an exception referencing IDs, keep it.
- In the competition screen, intercept the error and map:
  - `judge_id` → judge display label/name
  - `entry_id` → entry display number + name
- Render message with resolved names.

### I-260217-3.2 Add `x` delete binding + modal confirm

- Implement `action_delete_competition()` on home screen.
- Determine currently selected competition.
- Show a modal (or built-in confirm dialog).
- Confirm keys: `y` accept, `n` reject.
- On accept: apply S-260217-3.4 or fallback S-260217-3.5.

### I-260217-3.3 Soft-delete via `is_obsolete`

- Add `Competition.is_obsolete: bool = False`.
- Update persistence serialization/deserialization (if present) to include this field with default False.
- Filter home DataTable rows to exclude obsolete competitions.

### I-260217-3.4 Transcript panel default collapsed

- On competition screen mount, set transcript panel visibility to hidden.
- Keep toggle key/button unchanged.

### I-260217-3.5 Home table refresh

- Ensure home screen rebuilds DataTable rows on:
  - `on_mount` / `on_screen_resume`
  - or when navigating back from competition screen
- Prefer a single method like `refresh_table()`.

### I-260217-3.6 Yank copy

- Bind `y` on screens containing DataTables.
- Copy as TSV or CSV text (TSV recommended for spreadsheet paste).
- Use Textual clipboard API if available; otherwise minimal dependency.

### I-260217-3.7 Stretch: tie-break dead-cell cutoff

- If transcript already stores, for each entry, the cutoff column used (N), use that.
- Otherwise parse transcript steps to infer per-entry cutoff:
  - “1–3” implies cutoff=3
  - “1–4” implies cutoff=4
- Apply per-row styling: columns > cutoff are dead.
- Avoid altering algorithm decisions.
