# handoff-260217-2.md

## Scope / Problem framing

Implement small UI/UX improvements and export features for the Textual app (skating-system), without refactoring domain persistence/identity.

Primary goals:
- Bring vim-style navigation to the home competitions table (already present in the competition score matrix).
- Improve edit/open ergonomics from the home table (Enter should behave like `e`).
- Add “Duplicate competition” action with *pointer-preserving* semantics (cheap clone).
- Export **exactly what the user sees** in the active **Textual DataTable** to CSV.
- Optional: copy DataTable to clipboard (tab/CSV text) with a confirmation.

Non-goals:
- No domain model refactor.
- No “full computed table” export (only the visible DataTable).
- No Excel multi-sheet export in this handoff.

---

## Specs

### Navigation / keybindings

- **S-260217-2.1** Home competitions DataTable supports vim keys: `h/j/k/l` for left/down/up/right cell navigation.
  - Must not break arrow keys / existing navigation.
  - Only required for the **home/main competitions table** (not every table).

- **S-260217-2.2** Home competitions DataTable: `Enter` performs the same action as `e` (open/edit the selected competition).
  - Keep `e` as-is; do not remove or change it.

- **S-260217-2.3** Footer/help bar: do **not** show “keybinding hints spam” for `Enter` (and generally keep key-hint noise low).
  - Still allowed to show short confirmations for explicit actions (e.g., export success, copy-to-clipboard).

### Duplicate competition

- **S-260217-2.4** Add a “Duplicate competition” action from the home screen.
  - Trigger: choose a keybinding (suggestion: `d`) and/or a menu/button if one exists.

- **S-260217-2.5** Duplicate semantics (cheap clone): create a *new Competition object* and append it to the same Event.
  - New competition has:
    - New ID/UUID (whatever the project uses for new competitions).
    - New name derived from source name (see Implementation).
    - Same event association (same Event; appears on home list).
  - Pointer-preserving content:
    - Same `judge_ids` list contents (same IDs)
    - Same `entry_ids` list contents (same IDs)
    - Same `rank_marks` content (copy the list values; OK if shallow, as long as editing marks in either affects both only if underlying objects are shared; see note below)
    - Same `results` content (if present)

- **S-260217-2.6** No domain “safety” requirements for duplicated objects.
  - The UX intent is spreadsheet-like. If a user wants different judges/entries after duplication, they can remove/add them manually.

### Export: visible DataTable → CSV

- **S-260217-2.7** Export **exactly what the user sees** in the currently active DataTable.
  - Includes:
    - Visible column headers (in their current order)
    - Visible row order
    - Visible cell values as strings
  - Excludes:
    - Any hidden/internal columns not rendered
    - Any “full computed table” data that isn’t on screen

- **S-260217-2.8** Export format: CSV file.
  - Delimiter: comma
  - Quoting: use Python `csv` module default safe quoting (or explicit QUOTE_MINIMAL)
  - Newlines: platform-safe (newline="")

- **S-260217-2.9** Export destination:
  - Default: write in a predictable local directory (suggest: `./exports/` relative to cwd, auto-create).
  - Filename includes event + competition + timestamp when available.

- **S-260217-2.10** After export, show a short confirmation message (not keybinding hints) including the output path.

### Optional: Copy DataTable to clipboard

- **S-260217-2.11 (optional)** Add `Ctrl+C` to copy the current DataTable contents.
  - Copy format: either CSV text or TSV text (pick one; TSV often pastes better into spreadsheets).
  - Must show confirmation: “Table copied to clipboard”.

## Implementation suggestions

### I-260217-2.1 Add/extend home table keybindings

- Identify the home screen DataTable widget.
- Implement `on_key` handler mapping:
  - `h` → move cursor left
  - `j` → move cursor down
  - `k` → move cursor up
  - `l` → move cursor right
- If Textual provides built-in cursor movement actions, prefer calling those.

### I-260217-2.2 Enter triggers open/edit

- Reuse the existing code path for `e`.
- Bind `enter` to call the same action method.
- Ensure it works whether focus is on the DataTable or a container widget.

### I-260217-2.3 Reduce footer key-hint noise

- If there is a help/footer widget that prints keybinding hints automatically, disable it for `enter` or in general.
- Keep short, explicit action confirmations (export/copy) via a status message.

### I-260217-2.4 Duplicate competition action

- Add a new action method `action_duplicate_competition()` on the home screen.
- Determine currently selected competition from DataTable selection.
- Create a new Competition via a dedicated helper:

  - `duplicate_competition(event, competition_id) -> new_competition_id`

- Name strategy:
  - If name is `"<base>"`, new name default: `"<base> (copy)"`
  - If already ends with `"(copy)"` or `"(copy N)"`, increment N.

- Data copy semantics:
  - competition-level fields copied as specified in S-260217-2.5.
  - Implementation detail: if `rank_marks` is a list of mutable objects, consider `copy.deepcopy` only for that list if you want independent editing.
    - However: do **not** refactor domain; choose the simplest method that matches “clone as-is”.

### I-260217-2.5 Export visible DataTable to CSV

- Implement a small utility:

  - `datatable_to_rows(dt) -> (headers: list[str], rows: list[list[str]])`

- Extract:
  - headers: from DataTable columns (visible labels)
  - rows: iterate the DataTable rows in visible order
  - cells: stringify values (safe for None)

- Write CSV with `csv.writer`.

- Wire an action on relevant screens where a DataTable exists:
  - At minimum: competition screen score matrix DataTable
  - Plus: home competitions DataTable if useful

- Keybinding suggestion:
  - `x` for export (or `E`), but pick something consistent with existing app bindings.

### I-260217-2.6 Clipboard copy (optional)

- Prefer a dependency-free approach if possible.
- Options:
  - If Textual provides clipboard API, use it.
  - Otherwise, use `pyperclip` as a lightweight dependency.

If a dependency is required, add it to `pyproject.toml` and document it.

## Tests

### T-260217-2.1 Duplicate competition creates new object

- Create an event with one competition.
- Duplicate it.
- Assert:
  - new competition id != old id
  - new competition name != old name
  - both competitions exist under same event

### T-260217-2.2 Duplicate competition preserves pointers/content

- Ensure duplicated competition has same judge_ids, entry_ids.
- Ensure rank_marks values are identical.
- If results exist, ensure results copied.

(If you decide to deep-copy rank_marks for independence, encode that expectation explicitly; otherwise test identity-sharing only where relevant.)

### T-260217-2.3 DataTable export produces correct CSV

- Build a DataTable with known headers/rows.
- Export.
- Read file back.
- Assert CSV content matches exactly what was in the DataTable.

### T-260217-2.4 Keybindings dispatch

- If the project has Textual pilot tests:
  - Validate `h/j/k/l` move cursor.
  - Validate `enter` calls the same action as `e`.
